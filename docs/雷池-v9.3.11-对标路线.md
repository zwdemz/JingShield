# 捷云鲸盾与雷池 SafeLine v9.3.11 对标路线

> 基线日期：2026-08-06。对标对象为雷池社区版公开仓库与 v9.3.11 发布说明。本文中的百分比是工程覆盖度估算，不是第三方检测成绩或安全效果承诺。

## 结论

捷云鲸盾适合定位为“轻量、单机、单二进制 WAF”，当前已经形成可运行的代理、防护、验证、管理 API、管理 UI 和 systemd 部署闭环，但不能宣称达到雷池的检测能力或生产成熟度。

- 当前可用边界：HTTP/HTTPS 多站点反向代理；基础 SQL/XSS 和可导入 RE2 规则；CC、IP 名单、人机验证；攻击运营、设备 API 与管理控制台。
- 当前最大差距：语义检测引擎、证书生命周期、通用 Web ACL/限速规则编排、Bot/企业身份认证与多节点集群。
- 合理阶段目标：先做到雷池常用单机管理面的约 50%～60%，形成适合中小站点的明确差异化产品。追求功能数量上的完全对齐不经济，也不能替代专项安全评测。

## 能力矩阵

| 能力面 | 雷池 v9.3.11 / 官方公开能力 | 捷云鲸盾当前状态 | 判断 |
|---|---|---|---|
| 反向代理 | Tengine 网关，多组件协作 | Go `ReverseProxy`，按 Host 动态路由多源站，请求体限额与可靠转发 | 已形成 HTTP 多站点闭环 |
| 注入检测 | 官方公开覆盖 SQLi、XSS、代码/命令注入、CRLF、XXE、SSRF、路径遍历等；检测器包含语法/语义分析体系 | SQL/XSS 共 36 条正则，覆盖 Query/Form/Cookie/JSON/文本/XML；支持自定义和导入规则 | 🟡 局部实现，核心差距最大 |
| CC / 限速 | IP 频率限制、挑战与 Web ACL | 滑动窗口、URL 频率、请求间隔、变异/穿盾检测、临时封禁 | 局部实现，尚无通用规则编排 |
| 人机验证 | Bot challenge、认证挑战 | 8 种挑战展示，HMAC token、一次性消费、PoW、签名 Cookie | 基础闭环已实现 |
| IP 策略 | Allow/Deny 与自定义规则 | IP/CIDR/通配符白、黑、临时黑名单 | 基础实现 |
| 站点与 HTTPS | 多站点、证书和证书 ID 等管理 | 精确/通配域名、动态源站、HTTP/HTTPS、静态证书和测试证书 | 🟡 入口已实现，缺多证书/ACME/到期告警 |
| 管理界面 | 成熟控制台；v9.3.11 增加本地时区 Today、深色模式和规则日志跳转等 | 登录、改密、仪表盘、站点、日志、IP、策略、用户、设备，响应式深色布局 | ✅ 首版管理闭环 |
| 日志分析 | 多条件筛选及规则联动 | 五级风险、服务端分页、IP/类型/时间筛选、趋势、Top IP 和流式 CSV 导出 | 🟡 运营闭环已形成，缺规则命中跳转/SIEM 推送 |
| 身份与权限 | 社区/专业版能力持续演进，发布说明涉及 OIDC | 多管理员 Session、CSRF、管理 IP 白名单、首登改密和会话失效 | 🟡 基础实现，无 RBAC/OIDC/MFA |
| 架构与扩展 | PostgreSQL、管理、检测器、Tengine 等多容器组件 | 单 Go 进程 + MySQL + 进程内状态 | 轻量是优势，HA 是短板 |
| 运维升级 | 安装、版本升级和较完整生态 | 完整包、systemd、迁移/init、环境变量密钥、远程部署、校验和升级失败回滚 | ✅ 单机交付闭环，无集群滚动升级 |

## 分阶段路线

### P0：轻量单机闭环（当前）

已完成可运行入口、请求体转发、可信代理 IP、验证闭环、多站点、HTTP/HTTPS、管理鉴权、用户管理、数据库初始化、策略中心、攻击运营、首版 UI、单二进制嵌入、完整包和 Ubuntu systemd 部署。适用于受控环境、小流量站点和继续研发验证，不建议直接替代成熟 WAF 承载关键生产业务。

### P1：达到可试点水平

1. 完善现有站点模型：增加主动健康检查、独立超时与重试策略。
2. 完善证书生命周期：多证书绑定、导入、ACME 续期和到期告警；TLS 终止与测试证书已经实现。
3. 建立版本化 Web ACL：路径、方法、Header、参数、IP、频率、动作和优先级；提供规则命中日志跳转。
4. 补齐命令注入、路径遍历、CRLF、XXE、SSRF 等检测器，并建设真实正负样本回归集。
5. 增加配置导入导出、备份恢复和日志保留任务；安全升级/回滚脚本已经实现。

完成 P1 后，可作为少量非关键站点的灰度 WAF；工程覆盖度预计约为雷池常用单机功能的 50%～60%。

### P2：缩小检测质量差距

1. 从正则特征升级到规范化解析：多重 URL/HTML/Unicode 解码、内容类型感知和参数来源追踪。
2. 为 SQL、NoSQL、HTML/JS、Shell、路径、URL、XML 与 GraphQL 建立 tokenizer/AST 或有限状态检测，而不是继续堆叠正则。
3. 建立误报反馈、规则灰度、仅记录模式、规则命中解释和基准性能测试。
4. 完善自动化攻防回归与规则版本回滚；Ed25519 可信更新签名和安全 JSON 导入已经实现。

P2 是安全效果能否接近成熟 WAF 的决定性阶段；没有公开数据集上的召回率、误报率和吞吐延迟结果，不应使用“对标完成”表述。

### P3：生产与组织能力

Redis 状态实现、多节点一致性、集中控制面、RBAC/MFA/OIDC、审计、指标告警、无损升级和灾备属于此阶段。只有完成这些能力并通过长期生产验证，才适合讨论企业级替代。

## v9.3.11 具体 UI 对照

雷池 v9.3.11 的新增内容主要是控制台体验和依赖维护：按浏览器本地日历计算 Today、社区版/专业版深色主题、证书 ID、Allow/Deny 自定义规则命中数跳转日志、PostgreSQL 维护升级、GeoIP 更新及许可/OIDC 修复。捷云鲸盾首版 UI 已采用深色主题并具备日志筛选，但日期时区筛选、证书 ID、规则命中跳转、OIDC 和在线 GeoIP 更新均未实现，应分别归入 P1 或 P3。
