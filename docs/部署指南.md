# JingShield 部署指南

JingShield 支持在线部署和离线部署两种方式。两种方式最终都使用同一套 `run.sh` 完成数据库迁移、管理员初始化、证书准备和 systemd 服务启动。

## 一、部署方式选择

| 方式 | 适用场景 | 目标机是否需要访问互联网 |
|---|---|---|
| 在线部署 | 新服务器、可访问发行站点 | 需要，仅下载发行包和可选安装 MySQL 客户端 |
| 离线部署 | 内网、等保环境、隔离区 | 不需要，提前准备完整发行包和数据库 |

生产环境建议由联网跳板机下载并校验发行包，再将完整包传入目标服务器；目标机不需要 Go、Node.js 或源码构建环境。

如果直接在本项目仓库根目录执行 `bash run.sh`，脚本会自动识别以下文件并进入本地离线安装模式：

```text
bin/jingshield-linux-amd64
configs/config.yaml
deploy/linux/jingshield.service
```

该模式完全在当前仓库目录内运行：不会写入 `/opt` 或 `/etc`，不会注册 systemd；只会在仓库目录内生成 `jingshield`、`jingshield.env` 和 `jingshield.service`，并以前台方式启动。

## 二、在线部署

在线安装会从发行站点下载指定架构的完整包，并校验 SHA-256。

```bash
curl -fsSL https://release.example.com/jingshield/install.sh | \
  sudo bash -s -- --version 0.1.0 --admin-user admin
```

指定安装目录或使用远程已有数据库：

```bash
curl -fsSL https://release.example.com/jingshield/install.sh | \
  sudo bash -s -- \
  --install-dir /opt/jingshield \
  --skip-db-provision \
  --secrets-file /root/jingshield.values \
  --consume-secrets
```

在线部署前应准备 MySQL 客户端。脚本在交互环境会询问是否自动安装，在非交互环境会按系统包管理器自动安装。

## 三、离线部署

在联网环境准备对应架构的完整包：

```text
jingshield-<version>-linux-amd64.tar.gz
jingshield-<version>-linux-amd64.tar.gz.sha256
```

在联网环境校验：

```bash
sha256sum -c jingshield-<version>-linux-amd64.tar.gz.sha256
```

将 tar.gz 复制到目标机后执行：

```bash
tar -xzf jingshield-<version>-linux-amd64.tar.gz
cd jingshield-<version>-linux-amd64
sudo ./run.sh --admin-user admin
```

离线安装不下载源码或依赖，但目标机仍需要：

- systemd
- `mysql` 客户端
- 可访问的 MySQL 服务

如果目标机没有 MySQL 客户端，应在离线介质中提前准备对应发行版的软件包并安装。

如果本地 `jingshield@127.0.0.1` 账号已经存在但项目目录没有 `jingshield.env`，交互执行 `sudo bash run.sh` 时脚本会安全地提示输入该账号密码；不会自动重置已有数据库账号密码。非交互执行必须显式提供 `JINGSHIELD_DB_PASS`。

## 四、数据库安装向导

首次执行完整包内的 `run.sh` 时，脚本就是数据库安装向导：

1. 读取数据库连接参数
2. 自动生成数据库密码和 Session 密钥
3. 本地 MySQL 自动创建数据库和最小权限账号
4. 执行幂等数据库迁移
5. 如果数据库为空，交互式初始化管理员账号
6. 启动 JingShield 服务

本地 MySQL 自动创建账号时，默认使用：

```text
数据库：jyj_ccpro
账号：jingshield
主机：127.0.0.1
```

首次安装推荐：

```bash
sudo ./run.sh --admin-user admin --admin-email security@example.com
```

已有数据库或远程数据库不由 JingShield 创建时：

```text
sudo ./run.sh --skip-db-provision --secrets-file /root/jingshield.values
```

此时必须提供 `JINGSHIELD_DB_PASS`，脚本不会尝试创建数据库账号。

## 五、数据库和密钥配置

推荐通过权限为 `0640` 的环境文件配置敏感信息：

```ini
JINGSHIELD_DB_HOST=10.0.0.20
JINGSHIELD_DB_PORT=3306
JINGSHIELD_DB_USER=jingshield
JINGSHIELD_DB_NAME=jyj_ccpro
JINGSHIELD_DB_PASS=请替换为数据库密码
JINGSHIELD_SESSION_KEY=请替换为至少32字节随机密钥
```

也可以在 `config.yaml` 中配置非敏感参数：

```yaml
database:
  host: "10.0.0.20"
  port: 3306
  user: "jingshield"
  pass: ""
  name: "jyj_ccpro"

session:
  secret: ""
```

环境变量优先于配置文件。敏感值优先使用环境变量，不建议明文写入 `config.yaml`。

支持的环境变量包括：

```text
JINGSHIELD_DB_ADMIN_PASS
JINGSHIELD_DB_PASS
JINGSHIELD_SESSION_KEY
JINGSHIELD_DB_HOST
JINGSHIELD_DB_PORT
JINGSHIELD_DB_USER
JINGSHIELD_DB_NAME
JINGSHIELD_UPSTREAM
JINGSHIELD_LISTEN
JINGSHIELD_TLS_LISTEN
JINGSHIELD_TLS_CERT_FILE
JINGSHIELD_TLS_KEY_FILE
```

## 六、配置文件优先级

```text
环境变量 > config.yaml > 程序默认值
```

安装生成的配置位置：

```text
/opt/jingshield/config.yaml
/opt/jingshield/jingshield.env
```

修改静态配置后重启服务：

```bash
sudo systemctl restart jingshield
```

动态安全策略通过管理后台或 API 修改，不需要重启。

## 七、安装后检查

```bash
sudo systemctl status jingshield --no-pager
curl -k https://127.0.0.1:18443/
sudo journalctl -u jingshield -n 100 --no-pager
```

生产环境必须继续完成：

- 替换 30 年自签名测试证书
- 收紧 `admin_ips`
- 限制源站只允许 JingShield 节点访问
- 配置 HTTPS 和 Secure Cookie
- 定期备份 MySQL 与 `/opt/jingshield/config.yaml`

## 八、升级与回滚

```bash
tar -xzf jingshield-<new-version>-linux-amd64.tar.gz
cd jingshield-<new-version>-linux-amd64
sudo ./upgrade.sh
```

升级脚本会先迁移数据库，再替换程序；启动或健康检查失败时自动恢复旧版本程序。

## 九、Windows 离线部署

Windows 使用预构建的 `jingshield.exe`、`config.yaml`、`jingshield.env` 和 PowerShell 脚本，不需要联网下载依赖：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
& 'C:\ProgramData\JingShield\run.ps1' -Initialize
```

数据库密码和 Session 密钥写入 `jingshield.env`，不要写入公开的配置模板。
