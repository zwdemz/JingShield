## 一、项目简介

### 1.1 项目背景
捷云鲸盾（JieYun JingShield）是一款**原创**的 Web 安全防护系统，借鉴主流 WAF 产品的防护理念与工程实践自主设计实现。系统采用独立反向代理架构部署于被保护站点前端，对进入的 HTTP 请求执行 CC 攻击防护、XSS/SQL 注入检测、IP 黑白名单等安全检查，干净请求转发至后端真实站点，攻击请求在代理层拦截或引导人机验证。

### 1.2 设计目标
采用 **Go 反向代理型 WAF + Vue3 管理后台 + 开放 REST API（设备联动）** 架构：
- **部署形态**：独立反向代理，站前拦截
- **状态层**：进程内内存共享状态（`sync.Map` + 滑动窗口，预留 Redis 多副本扩展）
- **后台**：Vue3 SPA + Go REST API，前后端分离
- **能力扩展**：设备联动开放 API（状态查询、联动封禁/解封、订阅攻击事件）
- **安全加固**：覆盖 9 项常见 WAF 安全风险加固

### 1.3 核心能力
| 能力 | 说明 |
|---|---|
| 防护站点 | 精确域名/IP 与 `*.example.com` 通配域名，按 Host 动态选择源站、启停和 Host 透传 |
| 源站 TLS | HTTPS 默认校验证书；可信内网自签名源站可按站点显式跳过校验 |
| CC 攻击防护 | 普通频率 / TCP 连接 / 变异 CC / 穿盾 CC / URL 频率 / 请求间隔 / 端口扫描，8 种验证模式 |
| XSS 防护 | 10 条正则特征检测 |
| SQL 注入防护 | 26 条正则特征检测 |
| IP 管理 | 白名单 / 黑名单 / 临时黑名单，CIDR 与通配符 |
| 海外 IP 拦截 | 改用 QQWry 精准归属地判断（避免 /8 段误杀） |
| IP 归属地 | 纯真 QQWry.Dat 二进制库查询 |
| 日志管理 | 访问日志 / 攻击日志 / 登录日志，分页查询与统计 |
| 验证流程 | 5 秒盾 / 滑动 / 点击 / 302 跳转 / JS 跳转 / 旋转 / 安全检测 / 人机滑块 |
| 设备联动开放 API | 状态与 IP 联动；CEF、LEEF、Suricata EVE、Wazuh、通用 JSON 事件归一化；高危 IP 自动临时封禁 |
| 策略中心 | RE2 自定义规则、事务化离线导入、Ed25519 签名自动更新、基于开关与实时流量的优化建议 |
| 本机资源监控 | CPU、内存、磁盘、日志目录、业务请求速率，15 秒前端刷新与动态告警阈值 |

## 四、环境配置说明

### 4.1 开发环境
| 项 | 版本要求 |
|---|---|
| Go | 1.25+（`go.mod` 当前声明 1.25，实测 1.25.5） |
| Node.js | 20.19+ 或 22.12+（实测 24.18.1） |
| npm | 10+（实测 11.16.0） |
| MySQL | 5.7+ |
| 操作系统 | Windows 10 / Linux |

### 4.2 数据库准备
1. 确保配置的 MySQL 用户具有创建数据库和表的权限。
2. 执行 `jingshield migrate`；命令会按配置创建数据库、九张业务表及缺失的默认配置，重复执行不会覆盖已有数据。
3. 放置纯真 IP 库文件至 `data/QQWry.Dat`。

### 4.3 配置文件
复制 `configs/config.yaml`，按实际环境修改 `database`、`upstream.target`、`admin_ips`。敏感字段（DB 密码、会话密钥）优先用环境变量注入。

### 4.4 前后端联调环境

后端先监听 `127.0.0.1:18080`，再在另一个终端启动 Vite：

```powershell
cd web
npm install
$env:JINGSHIELD_DEV_API='http://127.0.0.1:18080'
npm run dev
```

访问 `http://127.0.0.1:5173/admin/`。Vite 只代理 `/api`，登录 Cookie、CSRF 和首次登录强制改密均走真实 Go 管理 API。生产环境不运行 Vite：先执行 `npm run build` 生成 `web/dist`，再构建 Go，管理界面会被嵌入二进制并通过 `/admin/` 提供。

## 五、项目启停启动命令

### 5.1 构建后端
```bash
cd jingshield
go mod tidy
go build -o jingshield.exe ./cmd/jingshield      # Windows
go build -o jingshield ./cmd/jingshield          # Linux
```

### 5.2 初始化（建表 + 默认配置 + 随机管理员密码）
```bash
./jingshield migrate -c configs/config.yaml
./jingshield init   -c configs/config.yaml      # 打印初始管理员账号与随机密码
```

`init` 会先自动执行幂等迁移，因此空库也可以直接运行；若 `jyj_users` 已有用户则拒绝覆盖。可用 `--username` 和 `--email` 设置初始管理员信息，同时生成设备 API Key。

### 5.3 启动服务
```bash
./jingshield -c configs/config.yaml            # 默认前台运行
```

### 5.4 前端构建与内嵌
```bash
cd web
npm ci                                       # 首次无 lock 时使用 npm install
npm run build                                # 产物输出 web/dist
cd ..
go build -o jingshield ./cmd/jingshield      # embed.FS 内嵌 web/dist
```

`web/dist` 是 Go 编译输入。全新检出代码后必须先完成前端构建，再运行 `go build` 或 `go test ./...`。

### 5.5 停止
- 前台：`Ctrl+C`
- systemd/Docker 部署后由对应服务管理器停止进程。
- 动态配置由进程每 30 秒自动刷新；独立 `reload`/`stop` 子命令尚未实现。

### 6.1 表结构（10 张表）

| `jyj_config` | 系统配置（键值，含描述） |

### 6.2 设计要点
1. `jyj_access_log` 增加 `idx_ip_created_at(ip, created_at)` 索引，支撑 CC 子检测高频查询。
2. `jyj_config` 新增配置项：`api_key`（设备联动密钥）、`upstream_url`（反代目标）、`webhook_url`（事件推送，可选）。
3. 默认管理员改为**随机初始密码**，首次登录强制改密。

### 6.4 完整建表 DDL（由 `jingshield migrate` 子命令执行）
> 数据库 `jyj_ccpro`，字符集 utf8mb4，引擎 InnoDB。字段与 `internal/model/model.go` 实体一一对应。

```sql
-- 1) 系统配置表
CREATE TABLE IF NOT EXISTS `jyj_config` (
  `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `config_key`   VARCHAR(100)  NOT NULL,
  `config_value` TEXT          NULL,
  `config_desc`  VARCHAR(255)  NULL,
  `created_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_config_key` (`config_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统配置（键值）';

-- 2) IP 黑白名单表
CREATE TABLE IF NOT EXISTS `jyj_ip_list` (
  `id`           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `ip`           VARCHAR(64)  NOT NULL COMMENT 'IP/CIDR/通配符',
  `type`         TINYINT      NOT NULL DEFAULT 2 COMMENT '1=白名单 2=黑名单 3=临时黑名单',
  `reason`       VARCHAR(255) NULL COMMENT '加入原因',
  `expire_time`  DATETIME     NULL COMMENT '仅临时黑名单有效',
  `created_at`   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_type` (`type`),
  KEY `idx_ip` (`ip`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='IP 黑白名单';

-- 3) 攻击日志表
CREATE TABLE IF NOT EXISTS `jyj_attack_log` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `ip`            VARCHAR(64)  NOT NULL,
  `ip_location`   VARCHAR(255) NULL COMMENT 'QQWry 归属地',
  `host`          VARCHAR(255) NULL,
  `uri`           VARCHAR(500) NULL,
  `method`        VARCHAR(10)  NULL,
  `attack_type`   VARCHAR(50)  NOT NULL COMMENT 'CC攻击/XSS攻击/SQL注入/IP黑名单/海外IP拦截/穿盾攻击',
  `attack_detail` VARCHAR(500) NULL,
  `attack_count`  INT          NOT NULL DEFAULT 0,
  `status`        TINYINT      NOT NULL DEFAULT 1 COMMENT '1=已拦截 2=已放行',
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_ip_created_at` (`ip`, `created_at`),
  KEY `idx_attack_type` (`attack_type`),
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='攻击日志';

-- 4) 访问日志表
CREATE TABLE IF NOT EXISTS `jyj_access_log` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `ip`            VARCHAR(64)  NOT NULL,
  `host`          VARCHAR(255) NULL,
  `uri`           VARCHAR(500) NULL,
  `method`        VARCHAR(10)  NULL,
  `user_agent`    TEXT         NULL,
  `referer`       TEXT         NULL,
  `status`        INT          NOT NULL DEFAULT 200,
  `response_time` DECIMAL(10,3) NULL COMMENT '秒',
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_ip_created_at` (`ip`, `created_at`) COMMENT '支撑 CC 子检测高频查询',
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='访问日志';

-- 5) 文件校验表
CREATE TABLE IF NOT EXISTS `jyj_file_check` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `file_path`      VARCHAR(500) NOT NULL,
  `hash`           VARCHAR(64)  NOT NULL COMMENT '文件哈希',
  `last_check_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `status`         TINYINT     NOT NULL DEFAULT 1 COMMENT '1=正常 2=异常',
  PRIMARY KEY (`id`),
  KEY `idx_file_path` (`file_path`(191))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件校验';

-- 6) 用户表
CREATE TABLE IF NOT EXISTS `jyj_users` (
  `id`            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`      VARCHAR(50)  NOT NULL,
  `password`      VARCHAR(255) NOT NULL COMMENT '管理员密码哈希',
  `email`         VARCHAR(100) NULL,
  `status`        TINYINT      NOT NULL DEFAULT 1 COMMENT '1=启用 0=禁用',
  `must_change_password` TINYINT(1) NOT NULL DEFAULT 1 COMMENT '首次登录强制改密',
  `last_login_at` DATETIME     NULL,
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户管理';

-- 7) URL 过滤规则表
CREATE TABLE IF NOT EXISTS `jyj_url_rules` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `url_pattern` VARCHAR(500) NOT NULL,
  `action`      TINYINT     NOT NULL DEFAULT 2 COMMENT '1=允许 2=阻止',
  `created_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='URL 过滤规则';

-- 8) 验证失败次数表
CREATE TABLE IF NOT EXISTS `jyj_verify_fail` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `ip`             VARCHAR(64) NOT NULL,
  `fail_count`     INT         NOT NULL DEFAULT 0,
  `last_fail_time` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `created_at`     DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ip` (`ip`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='验证失败次数';

-- 9) 登录日志表
CREATE TABLE IF NOT EXISTS `jyj_login_log` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`    BIGINT UNSIGNED NOT NULL,
  `login_ip`   VARCHAR(64)  NOT NULL,
  `login_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_user_id` (`user_id`)
```

## 八、各模块功能适配说明

### 8.1 反向代理与保护链

保护链采用顺序检测，Go 用中间件链实现。`Engine.Evaluate()` 返回 `Decision`（Allow/Block/Verify），由 `proxy.ServeHTTP` 翻译为 HTTP 响应：

```
HTTP 请求
  → 请求体大小限制
  → RequestContext 构建（ip/ua/uri/method/get/post/cookie）
  → Engine.Evaluate 保护链：
       1. SystemStatusCheck   系统关闭→放行
       2. BlacklistCheck      黑名单→403 + logAttack
       3. WhitelistCheck      白名单→放行短路
       4. OverseaIPCheck      海外IP→403 + logAttack
       5. CCAttackCheck       频率/TCP/变异/穿盾/URL/端口/区间→验证页或403
       6. XSSCheck            →错误响应 + logAttack
       7. SQLInjectionCheck   →错误响应 + logAttack
  → Decision 翻译：
       Allow  → httputil.ReverseProxy 转发 upstream
       Block  → writeError（json/html）
       Verify → serveVerificationPage（cc1-cc7 静态页）
```

### 8.2 CC 检测引擎

| 子检测 | Go 模块 | 状态来源 |
|---|---|---|
| 主频率检测 | cc/frequency.go | 内存滑窗 `Store.HitAndCount` |
| TCP 连接检测 | cc/tcp.go | 内存计数 |
| 变异 CC 检测 | cc/variant.go | 内存（UA/参数/URL 多样性） |
| 穿盾检测 | cc/shield_bypass.go | 内存（请求间隔标准差<0.3） |
| URL 频率检测 | cc/frequency.go | 内存 `HitAndCount(ip+uri)` |
| 请求间隔检测 | cc/frequency.go | 内存 `LastRequestAt(ip)` |
| 端口扫描检测 | cc/frequency.go | 内存 `RecordPort(ip,port)` |
| 动态阈值 | cc/dynamic_threshold.go | `gopsutil` 真实 CPU 采样 |
| 验证失败上限 | cc/detector.go | DB 查询 |
| 临时黑名单 | cc/detector.go | DB |

### 8.3 状态层（内存共享，预留 Redis）
```
StateStore 接口（internal/store/store.go）
├── HitAndCount(key, windowSec)       滑动窗口计数
├── LastRequestAt(ip)                 最近请求时刻
├── RecordPort(ip, port, windowSec)  端口集
├── RecentIntervals(ip, n)            方差分析数据
├── ResetIP(ip)                       验证成功后清理
└── ClearAll()                        后台清理缓存
```
内存实现 `memory/memory.go`：`sync.Map` + 每 key 互斥锁 + 后台 GC 清理过期数据。预留 Redis 实现接口。

### 8.4 XSS / SQL 检测器
- XSS/SQL 特征检测（10 条 XSS、26 条 SQL 正则），`regexp.MustCompile` 包级预编译。
- 已逐条核对：仅用 `i/s` 标志 + 字符类 + 非贪婪，**无前瞻/反向引用**，Go RE2 100% 兼容。
- 遍历 GET/POST/Cookie 全部参数值检测。

### 8.5 QQWry IP 归属地
纯真 IP 库二进制搜索实现：
- 索引偏移与记录地址用 `binary.LittleEndian.Uint32` 解析
- 随机读取用 `os.File.ReadAt`
- GBK 转 UTF8 解码用 `x/text/encoding/simplifiedchinese.GBK.NewDecoder()`
- 重定向标记（flag=1/2）递归处理
- 查询结果 LRU 缓存

### 8.6 验证流程（8 模式）
- 8 模式枚举 `verify.Mode`，由 Go 内置统一验证页展示并调用 `/cc/verify`。
- 挑战 token 使用密码学随机 nonce 和 HMAC-SHA256，绑定客户端 IP、验证动作、签发/过期时间，并在进程内单次消费；浏览器还需提交服务端验证的 SHA-256 工作量证明。
- 5 秒模式强制等待 5 秒，其余模式至少等待 1 秒；无效、过期、重放或来源 IP 不匹配均计为验证失败。
- `cc_verified` cookie 加 **HMAC-SHA256 签名**（payload=ip|expiry）+ HttpOnly/Secure/SameSite，防伪造。
- 验证成功 → 移除临时黑名单 + 清零验证失败次数 + 清理内存状态 + 设签名 cookie。

### 8.7 IP 管理
- 白/黑名单查询委托 `repository.IPListRepo`。
- 海外 IP 判断**采用 QQWry 精准归属地**（含"中国"关键字即国内），避免 /8 段误杀。

### 8.8 后台前端（Vue3）

已实现登录、首次改密、今日安全态势、本机资源告警、攻击日志、访问日志、防护站点、IP 名单、策略中心、用户管理、安全设备联动和系统设置。策略中心支持 CRUD、离线导入、自动更新和优化建议；设备联动页展示格式矩阵、响应阈值与归一化事件。所有管理写请求携带内存中的 CSRF token，会话 Cookie 由浏览器同源管理。

暂未实现登录日志独立页面、按站点证书/ACME、可视化条件树规则编排、RBAC 和深色/浅色切换。当前 UI 使用深色海军蓝与青色安全控制台风格。

## 九、安全设计

### 9.1 鉴权体系
| 场景 | 方式 |
|---|---|
| 管理员后台 | 用户名 + bcrypt 校验 → session cookie（HttpOnly/Secure/SameSite） |
| 后台 IP 白名单 | `admin_ips`（CIDR/通配符），`iputil.MatchAdminIP` |
| 设备联动 API | `X-API-Key` 头，`crypto/subtle.ConstantTimeCompare` 常量时间比较 |
| 验证 cookie | HMAC-SHA256 签名，防伪造 |

### 9.2 安全加固清单
| # | 风险点 | 加固方案 |
|---|---|---|
| 1 | 配置文件明文 DB 口令 | `config.yaml` + 环境变量覆盖，不入库不进 git |
| 2 | 默认弱口令 | 初始化随机密码 + 首登强制改密 |
| 3 | API key 非常量时间比较 | `crypto/subtle.ConstantTimeCompare` |
| 4 | 海外 IP 硬编码 /8 段误杀 | QQWry 精准归属地判断 |
| 5 | CPU 采样恒返回 0 | `gopsutil` 真实 CPU 采样，动态阈值生效 |
| 6 | SQL 注入面 | `database/sql` 全参数化 |
| 7 | XSS 输出面 | `html/template` 自动转义 |
| 8 | 验证 cookie 裸值无签名 | HMAC 签名 + 安全属性 |
| 9 | 异常直接外泄 | `RecoveryMiddleware` 捕获封装 |

### 9.3 请求防护
- 请求体大小限制（`http.MaxBytesReader`）
- 禁止 HTTP 方法（OPTIONS/TRACE/PUT/DELETE/CONNECT/PATCH）
- 全局异常捕获，禁原生 panic/错误外泄

## 十、部署运维说明

### 10.1 部署模型
```
客户端 → [Nginx :80/:443] → [Go WAF 127.0.0.1:18080] → upstream（真实站点 :9000）
                ↓
              MySQL
```
被保护站点改为只监听内网，由 Go WAF 对外。验证页与后台由 WAF 自身提供。

### 10.2 单二进制交付
Go 构建产物为单一二进制，前端 `web/dist` 与验证页经 `embed.FS` 内嵌，无需额外文件（仅 `config.yaml` 与 `QQWry.Dat` 外挂）。

### 10.3 容器化（deploy/Dockerfile）
- 多阶段构建：前端构建 → Go 构建 → 最小运行镜像
- `docker-compose.yml` 含 WAF + MySQL

### 10.4 systemd（deploy/jingshield.service）
- 开机自启、崩溃重启
- 专用无登录系统用户运行，并启用 `NoNewPrivileges`、只读系统目录等加固
- 二进制位于 `/opt/jingshield/bin/`，配置和密钥分别位于 `/etc/jingshield/`
- 密钥通过权限为 `0640` 的 `jingshield.env` 注入，不写入 YAML
- 日志输出至 `/var/log/jingshield/`
- 测试部署模板见 `deploy/linux/`；生产需替换测试 upstream，并在 HTTPS 下启用 Secure cookie

### 10.5 日志
结构化 JSON，分通道：`system.log` / `access.log` / `attack.log`，按配置轮转。

### 10.6 运维命令
| 命令 | 作用 |
|---|---|
| `jingshield migrate` | 建表 + 默认配置 |
| `jingshield init` | 初始化向导（随机管理员密码） |
| `jingshield -c config.yaml` | 启动 |
| 自动热加载 | 进程每 30 秒刷新动态配置 |
| `Ctrl+C` / 服务管理器 | 优雅停止进程 |

## 十三、风险与边界

1. **部署模型**：独立反向代理，站前拦截。被保护站点需改为只监听内网，由 Go 反代对外。
2. **多节点横向扩展**：单机内存状态在多副本下计数分散。本期单机先行；`StateStore` 接口已预留 Redis，多副本时换实现即可，无需改业务代码。
3. **正则兼容**：现有 XSS/SQL 正则已验证 RE2 兼容；未来新增正则需避开前瞻/反向引用。
4. **QQWry 数据文件**：`QQWry.Dat` 需随二进制分发或外挂路径配置。
5. **验证页前端**：`cc4.html/cc7.html` 等静态页若含服务端模板占位，需改为纯前端 JS 计算 token/redirect 或 Go 模板注入。
