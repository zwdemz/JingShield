# 捷云鲸盾 JieYun JingShield - REST API 接口文档

> 版本：v1.1  日期：2026-08-05  管理前缀：`/api/v1`  开放前缀：`/openapi/v1`

---

## 一、通用约定

### 1.1 请求约定
- 统一前缀：`/api/v1`
- 请求体：`application/json`（除登录表单外）
- 字符集：UTF-8
- 鉴权方式：
  - **管理接口**（`/api/v1/*`）：session cookie，登录后下发
  - **设备联动开放接口**（`/openapi/v1/*`）：`X-API-Key` 请求头，不受管理来源 IP 白名单限制
- 管理接口的 POST/PUT/DELETE 请求还必须携带登录响应返回的 `X-CSRF-Token` 请求头。
- 初始管理员首次登录后，只能访问当前用户、改密和登出接口；改密成功后 session 作废，需重新登录。

### 1.2 统一响应格式
```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```
- `code`：0 表示成功，负数表示错误（见全局状态码）
- `message`：结果描述
- `data`：业务数据，错误时为 `null`

### 1.3 全局状态码说明

| 状态码 | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | 正常响应 |
| -1 | 系统内部错误 | 服务异常 |
| -2 | 数据库错误 | 数据库操作失败 |
| -3 | 参数校验失败 | 入参缺失或非法 |
| -100 | SQL 注入命中 | 防护层拦截 |
| -110 | XSS 命中 | 防护层拦截 |
| -112 | 验证失败次数过多 | 触发临时黑名单 |
| -113 | IP 黑名单 | 黑名单拦截 |
| -114 | 海外 IP 拦截 | 海外 IP 限制 |
| -115 | CC 攻击 | CC 防护拦截 |
| -401 | 未登录/未授权 | session 失效或 API key 缺失 |
| -403 | 无权访问 | 后台 IP 白名单拒绝 |
| -404 | 资源不存在 | 查询对象不存在 |

### 1.4 分页约定
列表接口统一分页参数：
- `page`：页码，从 1 开始
- `size`：每页条数，默认 10，最大 100
- 响应：
```json
{ "code": 0, "data": { "list": [], "total": 100, "page": 1, "size": 10 } }
```

## 二、认证接口

### 2.1 管理员登录
- **接口名称**：管理员登录
- **请求方式**：POST
- **接口 URL**：`/api/v1/auth/login`
- **业务场景**：管理员登录后台，下发 session cookie
- **入参**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| username | string | 是 | 1-50 字符 | 用户名 |
| password | string | 是 | 1-255 字符 | 明文密码 |

- **出参示例**：
```json
{
  "code": 0,
  "message": "登录成功",
  "data": { "user_id": 1, "username": "admin", "role": "admin", "csrf_token": "...", "must_change_password": true }
}
```
- **参数约束**：用户名不存在、账号停用或密码错误统一返回 `code=-3`，避免用户名枚举；成功登录写入登录审计日志。

### 2.2 登出
- **接口名称**：管理员登出
- **请求方式**：POST
- **接口 URL**：`/api/v1/auth/logout`
- **业务场景**：清除 session
- **入参**：无
- **出参示例**：`{ "code": 0, "message": "已登出" }`

### 2.3 当前会话
- **请求方式**：GET
- **接口 URL**：`/api/v1/auth/me`
- **出参**：当前用户、CSRF token 与是否必须改密；允许首次登录强制改密状态访问。

{ "code": 0, "data": { "trend": [ {"hour":"00","count":5}, {"hour":"01","count":8} ] } }

- **请求方式**：GET

| 字段 | 类型 | 必填 | 说明 |

### 5.2 新增 IP 名单

| 字段 | 类型 | 必填 | 约束 | 说明 |

- **接口名称**：查询/更新防护开关
- **请求方式**：GET / PUT
- **接口 URL**：`/api/v1/system/status`
- **GET 出参**：
```json
{ "code": 0, "data": { "system_status":1, "cc_protection_status":1, "xss_protection_status":1, "sql_protection_status":1, "oversea_ip_status":0 } }
```

- **业务场景**：一键启停各防护模块

### 6.4 清理缓存
- **接口名称**：清理内存状态缓存
- **请求方式**：DELETE
- **接口 URL**：`/api/v1/cache`
- **出参示例**：`{ "code": 0, "message": "缓存已清理" }`

### 6.5 本机资源与告警阈值

- `GET /api/v1/system/resources`：返回运行节点的主机/系统/运行时长、CPU、内存、日志所在磁盘、日志目录大小、最近一分钟业务请求数、当前阈值及 warning/critical 告警。
- `PUT /api/v1/system/alert-thresholds`：更新任意阈值子集，字段为 `cpu_percent`、`memory_percent`、`disk_percent`、`log_size_mb`、`request_rate`。
- CPU/内存/磁盘范围为 1-100%；日志和请求速率范围为 1-1048576 MB、1-1000000 请求/分钟。默认业务速率阈值为 600 请求/分钟（10 RPS）。
- 资源告警与 WAF CC 阈值相互独立，调整告警不会改变流量拦截策略。

## 七、用户管理接口（session 鉴权）

### 7.1 用户列表与创建

- `GET /api/v1/users`：返回全部管理员，不返回密码哈希。
- `POST /api/v1/users`：创建管理员，请求体为 `username`、可选 `email`、12-255 字符的临时 `password`。新用户首次登录必须修改密码。

### 7.2 启停与管理员重置密码

- `PUT /api/v1/users/{id}/status`：请求体 `{"enabled":true}`。不能停用当前账号或最后一个启用的管理员；停用后目标用户全部会话立即失效。
- `PUT /api/v1/users/{id}/password`：请求体 `{"new_password":"..."}`。设置临时密码、使目标会话失效，并要求其下次登录修改密码；当前管理员应使用个人改密接口。

### 7.3 修改当前用户密码
- **接口名称**：修改当前用户密码
- **请求方式**：PUT
- **接口 URL**：`/api/v1/users/password`
- **入参**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| old_password | string | 是 | 1-255 | 旧密码 |
| new_password | string | 是 | 12-255 | 新密码 |

- **出参示例**：`{ "code": 0, "message": "密码修改成功，请重新登录" }`
- **参数约束**：旧密码错误返回 `code=-3`

## 八、站点接口（session 鉴权）

### 8.1 源站健康检查

`GET /api/v1/sites/{id}/health`

- 对指定站点源站发起一次受限检查，请求超时为 5 秒，禁止跟随重定向。
- 返回 `healthy`、`status_code`、`latency_ms`、`upstream`；网络失败时返回 `error`。
- `healthy` 表示源站可连接且返回 HTTP 200-499；5xx 或连接失败视为异常。

## 九、API 联动配置与开放 API

### 8.1 管理端联动配置（session + CSRF）

- `GET /api/v1/integration`：读取启停状态、密钥掩码及已开放端点。
- `PUT /api/v1/integration/status`：请求体 `{"enabled":true}`，即时启停开放 API。
- `POST /api/v1/integration/api-key/rotate`：轮换密钥，完整 `api_key` 只在本次响应中返回，旧密钥立即失效。

### 8.2 开放接口鉴权

外部安全设备（蜜罐、IDS、SIEM 等）在每次请求中携带 `X-API-Key: <密钥>`。服务端使用常量时间比较；联动停用时返回 HTTP 503，密钥无效时返回 HTTP 401。开放接口不依赖管理 session，也不受 `admin_ips` 限制。

### 8.3 节点状态

- `GET /openapi/v1/status`
- 返回服务健康状态、WAF 总开关、站点总数、启用站点数和 UTC 服务时间。

### 8.4 联动封禁 IP

- `POST /openapi/v1/ip/block`
- 请求体：

```json
{"ip":"203.0.113.10","reason":"SIEM high-risk event","expire_seconds":3600}
```

`expire_seconds` 为 0 时永久封禁；临时封禁范围为 1-31536000 秒。IP 支持单个地址、CIDR 和 IPv4 通配规则。相同 IP 的现有黑名单会被替换，白名单记录不会被删除且仍优先放行。

### 8.5 联动解封 IP

- `POST /openapi/v1/ip/unblock`
- 请求体：`{"ip":"203.0.113.10"}`
- 删除该值对应的永久和临时黑名单，不删除白名单；响应中的 `removed` 是删除记录数。

### 8.6 安全设备事件接入

- `POST /openapi/v1/events/{format}`
- `format` 支持 `cef`、`leef`、`suricata`、`wazuh`、`json`。
- 请求体最大 1 MB；事件归一化为设备名、厂商、事件类型、1-10 严重度、事件 IP 和消息。
- Fortinet、Palo Alto、Check Point、华为、深信服等设备可使用其 CEF 输出，经 HTTPS collector/webhook 转发；本版本不直接监听 UDP/TCP Syslog。

通用 JSON 示例：

```json
{"device_name":"edr-01","vendor":"Generic EDR","event_type":"malware","severity":9,"event_ip":"203.0.113.10","message":"malware detected"}
```

管理接口：

- `GET /api/v1/device-events?page=1&size=20&vendor=Wazuh`：查看归一化事件。
- `GET /api/v1/integration/device-settings`：读取自动封禁设置。
- `PUT /api/v1/integration/device-settings`：设置 `auto_block_enabled`、`auto_block_severity`（1-10）和 `auto_block_seconds`（60-31536000）。

### 8.7 策略管理、导入与自动更新

- `GET/POST /api/v1/policies`：列出或创建策略。
- `PUT/DELETE /api/v1/policies/{id}`：更新或删除策略，成功后热加载。
- `POST /api/v1/policies/import`：导入 `jingshield.rules/v1` 规则包；原子替换 `import` 来源，不影响 `custom` 和 `auto` 来源。
- `GET/PUT /api/v1/policies/settings`：配置更新地址、周期与 Ed25519 公钥；公钥留空时保留原值。
- `POST /api/v1/policies/update-now`：立即下载并校验签名规则包。
- `GET /api/v1/policies/recommendations` 与 `POST /api/v1/policies/recommendations/apply`：读取并应用允许列表内的优化项。

规则字段 `target` 支持 `all/uri/args/headers/body/method`，`action` 为 1（拦截）或 2（仅记录），`priority` 为 1-10000。表达式使用 Go RE2，不支持回溯引用与前后向断言。规则包示例：

```json
{"schema":"jingshield.rules/v1","version":"2026.08.05","rules":[{"name":"阻止敏感路径","category":"access","target":"uri","pattern":"(?i)^/private/","action":1,"enabled":true,"priority":100,"description":"示例规则"}]}
```

在线响应是 JSON 信封：`payload` 为规则包 JSON 的 Base64/Base64URL，`signature` 为 Ed25519 对原始 payload 字节的签名。客户端仅访问公网 HTTPS，限制 2 MB 和 3 次重定向，并在连接阶段再次阻断内网/回环/链路本地地址；验签或导入失败时保留现有自动规则。

### 8.8 当前未实现

UDP/TCP Syslog 监听、攻击事件 SSE、webhook、厂商专有 SDK、每设备独立密钥和细粒度 API scope 尚未实现。未定义的 `/openapi/v1/*` 路径固定返回 404，不会转发到业务源站。

## 十、验证接口（浏览器内部调用）

### 9.1 提交验证
- **接口名称**：CC 验证提交
- **请求方式**：POST
- **接口 URL**：`/cc/verify`
- **业务场景**：验证页前端 JS 调用，完成人机验证
- **入参**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| action | string | 是 | verify_5second/verify_slide/verify_click/verify_302/verify_jsredirect/verify_rotate/verify_securitycheck/verify_human |
| token | string | 是 | 服务端签发的短期、单次验证 token，绑定 IP 与 action |
| proof | string | 是 | 浏览器计算的 SHA-256 工作量证明 |

- **出参示例**：
```json
{ "status": "success", "message": "验证成功" }
```
- **成功副作用**：移除临时黑名单 + 清零验证失败次数 + 设签名 cookie `cc_verified`
- **参数约束**：token 过期、重放、来源 IP/action 不匹配或过早提交均失败；失败累计达 `cc_verify_fail_limit` 则拉入临时黑名单

## 十一、接口联调说明

1. 管理接口需先调 `/api/v1/auth/login` 获取 session cookie，后续请求自动携带。
2. 设备联动接口需在后台“API 联动”页面轮换生成 Key，请求头携带 `X-API-Key`。
3. 所有列表接口支持 `page`/`size` 分页。
4. 时间字段统一 `YYYY-MM-DD HH:MM:SS`（本地时区）。
5. IP 字段支持 IPv4，名单支持 CIDR 与通配符写入（如 `192.168.1.0/24`、`10.*.*.*`）。
